# AgentLab v0.2: AWS Fabric Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Run AgentLab experiments on AWS infrastructure we build ourselves (SQS, EventBridge Pipes, Step Functions, Fargate, DynamoDB, S3), finishing by reproducing experiment 001's PROMOTE verdict in the cloud.

**Architecture:** `agentlab cloud submit` enqueues an experiment spec to SQS; an EventBridge Pipe starts a Step Functions Standard execution; the state machine runs each arm as an ARM64 Fargate task via the ECS `.sync` pattern, then a finalize task computes stats, verdict, and report; workers write state transitions to DynamoDB idempotently and artifacts to S3; everything is Terraform-managed, tagged, budget-alarmed, and torn down with one command. Model calls authenticate via the Fargate task role (no credential helper needed in the cloud; that was a laptop-only problem).

**Tech Stack:** Terraform (pending Daniel's install OK), Docker (ARM64 image), boto3, moto (dev, AWS mocking), existing agentlab package (Inspect runs the evals inside the container exactly as locally).

**Spec:** `docs/phase0-synthesis.md` sections 4-6 (fabric = deliberately hand-built learning curriculum; security model; region/posture defaults) plus these measured inputs from v0.1: a sized run is 510 evals, ~16 min at 30 connections, $0.54 on Nova; EvalLogs ~1-2MB per arm; Fargate quota verified at 64 vCPUs; account 123456789012, eu-west-1.

## Global Constraints

- Never use the em dash character anywhere; use "-".
- Markdown prose: each full sentence on its own line.
- Commit messages: NO co-author or agent-name lines.
- ruff + full pytest clean at every commit; `terraform fmt -check` and `terraform validate` clean at every commit that touches infra/.
- Tests never call live AWS: moto for AWS APIs, mockllm for models. Live verification happens only in the deploy tasks (6-8), explicitly.
- Region eu-west-1; ARM64 (Graviton) images and task definitions; public subnets with `assignPublicIp=ENABLED`; NO NAT gateway, NO load balancer, NO VPC endpoints except free gateway endpoints for S3 and DynamoDB.
- Every Terraform resource carries `tags = { project = "agentlab" }`; workers add `experiment_id` tags/attributes on artifacts and metrics. NEVER use experiment_id as a CloudWatch metric dimension.
- IAM: task role gets ONLY bedrock:InvokeModel* (plus Converse), scoped S3 prefix read/write, scoped DynamoDB table access; execution role gets only ECR pull + CloudWatch logs. No wildcards on resources where an ARN is knowable.
- CloudWatch log groups get explicit 30-day retention.
- AWS API/ARN specifics (the ECS `.sync` integration shape, Pipes target syntax, Bedrock IAM action names) MUST be verified against current AWS docs at execution time; the shapes in this plan are intent, not verified gospel.
- Cost guardrail: an AWS Budget with a $50 monthly alarm to Daniel's email is created in Task 2 BEFORE any compute infra exists.
- The existing local CLI stays untouched and working; cloud commands are additive.

### Task 1: Worker commands (cloud execution entrypoints, fully offline-testable)

**Files:**
- Create: `src/agentlab/worker.py`, `tests/test_worker.py`
- Modify: `src/agentlab/cli.py` (register `worker` sub-app)

**Interfaces:**
- Produces: `agentlab worker run-arm` reading env vars EXPERIMENT_ID, ARM_STYLE, MODEL, TASKS, REPEATS, N_FACTS, FILLER_TURNS, SUMMARY_BUDGET, MAX_CONNECTIONS, RESULTS_BUCKET, STATE_TABLE; runs the existing eval for one arm (reuse `_run_arm` machinery via a thin async call), uploads the EvalLog to `s3://$RESULTS_BUCKET/experiments/$EXPERIMENT_ID/logs/`, and writes DynamoDB state transitions.
- Produces: `agentlab worker finalize` reading the same env plus both arms' styles; downloads both EvalLogs, reuses `extract_results`/`paired_analysis`/`verdict`/`render_report`, writes `report.md` to S3 and the final verdict item to DynamoDB.
- DynamoDB item shape (table `agentlab-state`, PK `experiment_id`, SK `event#<iso-ts>#<event>`): fields event (CREATED|ARM_STARTED|ARM_COMPLETED|ARM_FAILED|FINALIZED), arm, detail, ts. Writes use `attribute_not_exists` conditional puts keyed on the full SK for idempotency; a retried task re-emitting an event must not duplicate or crash (condition failure is swallowed as already-recorded).
- Consumes: everything from v0.1 (`_run_arm`, `extract_results`, stats, report).

- [ ] **Step 1: Write failing tests** with moto (`@mock_aws`) + mockllm: run-arm on a 2-seed/1-repeat mockllm config uploads a log object to the mocked bucket and writes ARM_STARTED + ARM_COMPLETED items; finalize on two pre-seeded mock logs writes report.md to S3 and a FINALIZED item whose verdict matches the local pipeline on the same logs; idempotency test: calling run-arm's transition writer twice yields one item, no exception.
- [ ] **Step 2: Run tests, confirm import failure.**
- [ ] **Step 3: Implement** worker.py (boto3 clients built from env/region; pure helpers `transition(table, experiment_id, event, arm, detail)` and `upload_log(bucket, experiment_id, path)` for testability).
- [ ] **Step 4: Full suite + ruff, confirm green.**
- [ ] **Step 5: Commit** "feat: cloud worker commands with idempotent state transitions".
